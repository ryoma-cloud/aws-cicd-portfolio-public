# 外部連携方式設計

## 1. ID管理システム

### 1.1 連携概要

| 項目 | 方式 |
| --- | --- |
| 方向 | ID管理システム → 本システム |
| タイミング | 随時 |
| 受付単位 | 1要求につき1人分 |
| 通信・形式 | REST API／HTTPS、JSON形式 |
| 受付基盤 | API Gateway → 社員情報受付Lambda → SQS |
| 登録基盤 | SQS → 社員情報登録Lambda → Aurora Writer |
| 認証 | ID管理システムによるIAM署名付きリクエスト |

### 1.2 連携データ

| 項目 | 用途 | 必須 |
| --- | --- | --- |
| 社員番号 | 入館証発行対象の識別・主キー | ○ |
| 氏名 | 入館証発行依頼に使用する氏名 | ○ |
| 所属会社名 | 入館証発行対象者の所属会社 | ○ |

### 1.3 受付・登録の成立条件

#### 1.3.1 API受付

| 条件 | 本システムの扱い | ID管理システム側の扱い |
| --- | --- | --- |
| 入力が有効でSQS登録が完了 | `202 Accepted`を返す | 要求受理として扱う |
| 入力不正 | `400 Bad Request`を返す | 入力を修正して再連携 |
| SQS登録失敗 | `500 Internal Server Error`を返す | 障害解消後に再連携 |

`202 Accepted`は要求を保持したことを意味する。応答時点では、DB登録や入館証発行依頼の完了を保証しない。

#### 1.3.2 非同期登録

| 既存データとの関係 | 登録結果 |
| --- | --- |
| 社員番号が未登録 | 入館証番号を採番し、新規登録 |
| 社員番号・氏名・所属会社名がすべて一致 | 既存データを維持し、正常終了 |
| 同じ社員番号で氏名または所属会社名が不一致 | 既存データを維持し、対象要求をDLQへ隔離して監視通知 |

## 2. カード発行業者

### 2.1 連携概要

| 項目 | 方式 |
| --- | --- |
| 方向 | 本システム → カード発行業者 |
| タイミング | 日次 |
| 送信元 | S3 |
| ファイル形式 | CSV |
| 送信 | Transfer Family SFTP Connector／SFTP |
| Connector出口 | Service managed egress |
| 連携完了 | ファイルのSFTP送信完了 |

### 2.2 送信データ

| 項目 | 出所 |
| --- | --- |
| 社員番号 | ID管理システムから受信した値 |
| 氏名 | ID管理システムから受信した値 |
| 所属会社名 | ID管理システムから受信した値 |
| 入館証番号 | 本システムにて採番 |

### 2.3 ファイル授受の条件

| 観点 | 方針 |
| --- | --- |
| 初回送信 | 作成したファイル名にて送信 |
| 再送 | 同名・同内容にて再送 |
| 送信中の名前 | 一時名での送信・送信後リネームは行わない |
| 対向側の責任 | 送信途中の取込防止、同名・同内容の二重業務処理防止 |
| 本システムの完了範囲 | SFTP送信完了までとし、入館証発行完了の受領は対象外 |

カード発行業者はPublic SubnetのEC2上でOpenSSH SFTPを使用して入館証発行依頼ファイルを受領する。本ポートフォリオのカード発行業者モックでは業務処理を模擬せず、同名・同内容の再送後に受領ファイルの内容を確認する。
対向側の取込防止・二重業務処理防止は実対向を想定した前提とし、本ポートフォリオのモックでは実装・検証しない。

### 2.4 送信結果・復旧

1. Connectorの送信結果をEventBridge経由で受け取る。
2. ファイル単位の送信状態をDBへ反映し、入館証発行依頼ファイルを結果に応じたS3配置へ変更する。
3. SFTP送信失敗時は監視通知し、運用ツールで保存済み失敗ファイルを手動再送する。

詳細は[処理方式設計](03_処理方式設計.md)と[運用監視基本設計](07_運用監視基本設計.md)に従う。

## 3. 通信・認証情報の保護

| 対象 | 方針 |
| --- | --- |
| API | HTTPS、ID管理システムによるIAM署名付きリクエスト |
| SFTP | 鍵認証、Connector送信元IP制限、対向ホスト鍵検証 |
| 保存データ | 暗号化、用途に必要な権限のみ付与 |
| 秘密情報 | Secrets Managerで管理し、GitHub・ソースコード・ログへ実値を残さない |

モックの設計・仕様は[ID管理システムモック](../11_対向システム/01_ID管理システム/ID管理システムモック.md)と[カード発行業者モック](../11_対向システム/02_カード発行会社/カード発行業者モック.md)を参照する。
