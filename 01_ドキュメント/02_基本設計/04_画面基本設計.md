# 画面基本設計

## 1. 画面・利用条件

入館証発行依頼状況を確認する参照画面を提供する。

| 観点 | 方針 |
| --- | --- |
| 利用端末・外観 | PC中心、スマートフォンでも閲覧可能。白背景と青を基調とする |
| アクセス | ALBのDNS名へHTTPで直接アクセス |
| 実行・参照 | ECS / Fargate上のWebアプリからAurora Reader endpointへ接続 |
| 更新 | 検索・ページ再読込時に取得、自動更新なし |
| データ鮮度 | Readerの短い反映遅延を許容 |
| 利用範囲 | 認証・認可・ユーザ管理は対象外 |

複雑な検索・集計・帳票、HTTPS化・独自ドメイン・証明書、再発行は対象外とする。

画面用のAPI Gateway・Lambdaは追加しない。登録・更新・削除・再送などの業務・保守操作は画面から行わない。

## 2. 表示項目

| 項目 | 表示内容 |
| --- | --- |
| 社員番号 | 入館証発行対象の識別情報 |
| 氏名 | 社員氏名 |
| 所属会社名 | 対象者の所属会社 |
| 入館証番号 | 本システムの採番結果 |
| 処理状況 | 下表の日本語名称 |
| 更新日時 | 最終更新日時、JST |

| 内部状態 | 画面表示 |
| --- | --- |
| `REQUESTED` | 入館証発行依頼待ち |
| `SENT` | 入館証発行依頼済み |
| `SEND_FAILED` | 入館証発行依頼失敗 |

初回送信の結果未確定時は「入館証発行依頼待ち」、再送の結果未確定時は「入館証発行依頼失敗」を維持し、送信中の独立表示は設けない。

## 3. 検索・一覧操作

### 3.1 検索条件

| 条件 | 動作 |
| --- | --- |
| 統合検索欄 | 氏名・社員番号・入館証番号を同じ検索欄から検索 |
| 一致条件 | 氏名の部分一致、社員番号の完全一致、入館証番号の完全一致のいずれか |
| 処理状況 | 日本語の状況で絞り込み。「すべて」は絞り込みなし |
| 条件の組合せ | 統合検索と処理状況の両方を満たす対象 |
| 未入力 | 統合検索の条件を適用しない |
| 複数該当 | 同姓同名を含め、該当者をすべて検索結果に含める |

所属会社名は表示のみとし、検索条件へ追加しない。

### 3.2 操作・結果表示

| 操作・結果 | 動作 |
| --- | --- |
| 初期表示 | 連携受付日時の新しい順で一覧表示 |
| 検索 | 検索ボタンで条件を適用し、データを再取得 |
| クリア | 検索欄・処理状況を初期状態へ戻し、一覧を再取得 |
| ページ再読込 | データを再取得 |
| 該当なし | 「該当する発行対象はありません。」を表示 |
| データ取得失敗 | 「データを取得できません。時間をおいて再度お試しください。」を表示し、再操作を促す。HTTP 503を返す |
| スマートフォン | 条件欄を縦に配置し、一覧は横スクロールで確認可能 |
