# セキュリティ・秘密情報 詳細設計

## 1. 設定値の表記・管理対象

構成定義：`02_資材/02_temporary/terraform/security.tf`、`02_資材/02_temporary/terraform/security-controls.tf`、`02_資材/02_temporary/terraform/secrets.tf`、`02_資材/01_persistent/security_evidence.tf`。

設定値は固定値とTerraform参照式で記載する。`<account-id>`は対象AWSアカウント、ID・ARN・endpoint等の自動採番値は表中のリソース参照で解決する。「未指定」はTerraformから明示設定しない項目を示す。

## 6. Backend S3のTLS拒否

環境Stateの外にあるbackend基盤として管理し、常設・一時環境の削除後も保持する。`tools/environment.py`の常設applyが既存Statementを維持して以下を追加・更新する。

| 意味 | パラメータ | 値 |
| --- | --- | --- |
| 対象バケット | `対象バケット` | `TF_STATE_BUCKET` |
| ポリシー言語のバージョン | `Version` | `2012-10-17` |
| ポリシーステートメントの識別子 | `Sid` | `PortfolioRequireSecureTransport` |
| アクセスの許可・拒否 | `Effect` | `Deny` |
| 操作主体 | `Principal` | `*` |
| 対象操作 | `Action` | `s3:*` |
| 対象リソース | `Resource` | `["arn:aws:s3:::<TF_STATE_BUCKET>", "arn:aws:s3:::<TF_STATE_BUCKET>/*"]` |
| HTTPS通信の条件 | `Condition.Bool.aws:SecureTransport` | `false` |

旧Stateに`aws_s3_bucket_policy.state_tls[0]`が残る場合は通常applyで管理を分離するまでdestroyを停止する。環境削除でbackendポリシーを削除しない。

## 7. 通知・是正・停止

通知条件は`Severity.Label=HIGH/CRITICAL`、`RecordState=ACTIVE`、`Workflow.Status=NEW`。GuardDuty・Inspector等の結果をSecurity Hub経由で選択し、EventBridgeからSNSへイベント全体を渡す。MEDIUM以下を一律メール通知しない。詳細は[EventBridge詳細設計](10_AWS_EventBridge.md)と[SNS詳細設計](15_AWS_SNS.md)に定める。

修正版がある場合は依存更新・再ビルド・CI・Inspector再検査・Terraform変更確認・業務疎通を行う。`fixAvailable=NO`だけで影響なしとせず、Finding ID・CVE・digest・影響・既存対策・見直し期限を記録して継続可否を判断する。

一時環境削除時は本環境所有の検査設定を停止・削除し、backendと常設Config証跡を保持する。IAM権限は[IAM詳細設計](02_AWS_IAM.md)、ログ保持90日と削除条件は[CloudWatch詳細設計](13_AWS_CloudWatch.md)に定める。
