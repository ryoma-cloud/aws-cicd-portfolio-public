# 基盤詳細設計

## 1. 基盤詳細設計方針

基盤詳細設計は、基本設計で定めた構成・非機能の実現方式を前提として、AWSリソースの構築・設定・テストに必要な具体的な仕様を定義する。

以下の方針に基づき作成する。

- AWSサービスごとに、リソース構成、設定値および関連リソースとの接続関係を明確にする。
- 設定値は、項目の意味、パラメータ名、値が分かる形式で記載する。
- ネットワーク配置、通信経路、IAM権限および秘密情報の管理方法を定義する。
- 可用性、スケーリング、タイムアウト、再試行およびバックアップに関する設定を具体化する。
- 監視対象、検知条件、ログおよび通知先との連携を定義する。
- 構築時に発行されるID・ARNや、認証情報・通知先は環境入力として区別し、秘密値を設計書へ記載しない。
- 設計値とTerraformの定義の整合性を保ち、変更時は関連する設計書も更新する。

設定の意味と採用理由を説明でき、構築担当者が設定を具体化し、テスト担当者が期待値を確認できることを重視する。
