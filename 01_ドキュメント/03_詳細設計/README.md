# 詳細設計

## 1. 詳細設計方針

詳細設計は、要件定義・基本設計を前提として、実装・構築・テストに必要な具体的な仕様を定義する。

以下の方針に基づき作成する。

- 基本設計で定めた構成・処理方式を、AWS設定およびアプリケーションの仕様へ具体化する。
- 入出力、処理順序、分岐、データ更新およびログを明確にする。
- タイムアウト、再試行、重複実行、部分失敗および復旧時の処理を定義する。
- DB・S3・外部システム間の整合性と、処理の成功・失敗の判定条件を明確にする。
- AWS設定値、IAM権限、通信経路および監視条件を定義する。
- 構築時に発行されるID・ARNや、認証情報・通知先は環境入力として区別し、秘密値を設計書へ記載しない。

実装者が処理と設定を具体化でき、テスト担当者が期待結果を判断できることを重視する。要件・基本設計の変更が必要な場合は、上位文書にも反映する。
