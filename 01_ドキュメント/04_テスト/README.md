# テスト

## 1. テスト方針

テストは、要件定義・基本設計・詳細設計に基づき、業務機能、データ整合性、外部連携、基盤および運用が定めた条件を満たすことを確認する。

以下の方針に基づき実施する。

- 正常系に加え、不正入力、重複実行、通信障害、部分失敗、再試行および復旧を確認する。
- 単体、DB結合、基盤構成、AWS実環境での業務・運用試験を区別し、確認対象に応じた方法を用いる。
- 各項目に実施条件、確認方法、期待結果および合否判定基準を定義する。
- 応答や処理結果に加え、DB・S3・対向システムの状態と、不要な副作用がないことを確認する。
- 可用性、自動増減、監視・通知、セキュリティ、構築・削除および再構築を対象に含める。
- 障害を発生させる試験では、対象と影響範囲を明確にし、試験後に環境を復旧する。

テスト仕様と実施結果を区別し、実施済み・未実施・確認不能を明確にする。構成の確認だけで実動作やメール受信まで確認したとは判定しない。

## 3. テストコードと検証範囲

CIで使用するワークフロー模擬実行テストは、[04_テスト/workflows/](../../04_テスト/README.md)に配置する。実行方法と検証範囲は同フォルダのREADMEに示す。

テスト仕様書・テスト項目表は、単体・DB結合・Terraform構成・AWS実環境を含むシステム全体の検証方針を定義する。収録する自動テストコードはワークフロー模擬実行テストに限り、その他の試験コード、実行結果、ログ・JSON・JUnit・coverage等の証跡は含めない。仕様・項目の記載自体は、試験の実施や合格を示すものではない。
