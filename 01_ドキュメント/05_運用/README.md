# 運用

## 1. 運用設計方針

運用設計は、基本設計・詳細設計を前提として、稼働状況の把握、障害対応、保守変更および停止・再開の方針と手順を定義する。

以下の方針に基づき作成する。

- 監視・メール通知を起点として、保守担当者が対象と影響を確認できるようにする。
- 障害ごとに、確認事項、復旧操作および復旧完了の判定条件を明確にする。
- 再送、DBへの結果再反映およびS3配置の復旧を区別し、重複送信とデータ不整合を防ぐ。
- バックアップ・ログ・CSVの保持と、復元時の確認事項を定義する。
- 変更・切り戻し、セキュリティ所見への対応および認証情報の更新手順を整理する。
- 費用抑制のための環境削除・再構築について、事前確認、削除対象および再開条件を明確にする。

保守担当者が状況に応じた操作を選択し、処理結果とデータの整合性を確認して運用を再開できることを重視する。
