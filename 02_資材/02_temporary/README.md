# 一時環境の資材

入館証発行管理の業務処理、Web画面、DBおよびAWS基盤を配置する。利用時に作成し、利用後に削除する環境として管理する。

## 1. 資材構成

| ディレクトリ | 役割 |
| --- | --- |
| [terraform/](terraform/README.md) | API受付、キュー、DB、Web、SFTP連携、監視・セキュリティのAWS構成 |
| `app/common/` | 入力検証、DB操作、CSV作成、送信結果反映などの共通処理 |
| `app/web/` | 入館証発行依頼の一覧・検索画面とヘルスチェック |
| `app/migrations/`、`app/tools/` | DBテーブル・権限の作成と更新 |
| `app/certs/` | DB接続時にサーバ証明書を検証するためのCA証明書 |
| `lambda/` | API受付、DB登録、日次処理、送信結果反映、再送の入口とID管理システムの送信処理 |
| `app/Dockerfile`、`app/requirements.lock` | Web・DB更新用コンテナの構成とPython依存ライブラリ |

構築・削除・状態確認・保守の処理は[ワークフロー資材](../../03_ワークフロー/02_資材/tools/README.md)で管理する。カード発行業者のSFTP接続先は、対向システムを模擬するEC2として構築する。

## 2. 構築時の依存関係

常設基盤の作成後、ワークフローで以下を順に実行する。

1. Lambdaの配布資材を生成し、Web・DB更新用コンテナをECRへ登録する。
2. SFTP接続先を作成・初期設定し、取得したホスト公開鍵を接続設定へ渡す。
3. DBなどの基盤を作成し、DBテーブルとアクセス権限を準備する。
4. DB更新の正常終了を確認してから、Webアプリケーションを反映する。

初回はWebタスク数を0として基盤とDBを準備し、DB更新後に2タスクで起動する。運用中のタスク数はApplication Auto Scalingが2～4の範囲で管理する。稼働済み環境でタスク数の入力を0にしても、Web停止操作にはならない。

コンテナは変更対象を特定できるdigestで指定する。SFTPの秘密鍵とDBパスワードはSecrets Managerへ保存し、Terraformには秘密鍵そのものを渡さない。

## 3. 実行・確認

作成・削除は[操作手順](../../03_ワークフロー/01_ドキュメント/03_操作手順.md)に従う。事前planとapplyは別runで実行し、apply時には再計画する。初回の事前planは先行構築部分が対象となるため、全体構成の変更予定をすべて示すものではない。

日次スケジュールは初回構築時には無効とし、準備完了を確認してから有効にする。既存環境を更新する際は、ワークフローが現在の有効・無効を引き継ぐ。

CloudWatch Logsの保持期間は90日とし、一時側で管理するロググループは環境削除時に削除する。DBは自動バックアップを7日保持するが、環境削除時の最終スナップショットは作成しない。

通常CIはPythonの構文確認、ワークフロー模擬実行、Terraformの書式・定義検証を行う。DB結合試験やAWS実環境での業務動作確認は、[テスト仕様書](../../01_ドキュメント/04_テスト/テスト仕様書.md)と[テスト項目表](../../01_ドキュメント/04_テスト/テスト項目表.md)に従って別途実施する。

全体の管理方針は[資材作成方針](../README.md)を参照する。
